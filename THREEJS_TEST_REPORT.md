# TrustDrive — Three.js / 3D Inspection Test Report

**Date:** 2026-11-05 · **Component:** `components/shared/Viewer3D.tsx` → `VehicleViewer3D.tsx`
**Route:** `GET /api/v1/vehicles/{id}/3d-model` + `GET /api/v1/vehicles/{id}/damage`

## Result: PASS — real GLB, no placeholder, DB-driven hotspots

### Asset verification (not a primitive)
- `public/models/vehicles/trustdrive-sedan.glb` — **11.7 MB**, real vehicle model.
  - `model-manifest.json`: 101 nodes, 97 meshes, **85 named meshes**, generated by RapidPipeline 3D
    Processor; SHA-256 recorded; dimensions 4.357 × 2.728 × 1.308 m.
- `public/models/car.glb` — present as **fallback only** (`FALLBACK_MODEL_URL`).
- `grep -rn "boxGeometry|sphereGeometry"` across `components` and `app` → **0 matches**. No primitive
  car placeholder ships (explicitly forbidden by AGENTS.md).

### Loading & modes
- `VehicleViewer3D.tsx` loads `PRIMARY_MODEL_URL = "/models/vehicles/trustdrive-sedan.glb"`; falls back
  to `car.glb` only on error.
- Four modes implemented: **Normal, Exploded, Damage, X-Ray** (matches the spec's "4 modes").
- 360° rotation, zoom, camera presets, component selection, component highlighting, fullscreen.

### Damage hotspots ↔ database
- `Viewer3D` receives `hotspots` as a **prop** (damage records pushed in from the page/API, not baked in).
- `GET /api/v1/vehicles/{id}/damage` returns **damage records + clickable 3D zones** (DB-backed:
  `damage_records`, `vehicle_components`).
- A seller-created damage record maps to a real component id and is visible to the authorized buyer.
- `GET /api/v1/vehicles/{id}/3d-model` returns the model manifest + component availability report.

### Findings
- Exploded view is supported by the named-mesh model; the checklist permits it when the model has
  separated parts (85 named meshes present).
- Hotspot coordinates are component-anchored; rotation is handled by the raycaster, so markers stay
  attached to the correct component.
